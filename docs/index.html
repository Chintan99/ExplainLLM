The idea

Generation is sequential.
Its explanation should be too.

At step t, the model sees the original prompt plus everything it has already generated. ExplainLLM computes a normalized relevance vector over that exact context, then repeats the process for the next token.

01 · Quickstart

Pick your entry point.

Use a tiny public model on CPU for a first run. Move to CUDA and a larger causal LM when the workflow feels right.

example.py
from explainllm import calculate_relevance, RelevanceConfig

config = RelevanceConfig(
    model_id="sshleifer/tiny-gpt2",
    device="cpu",
    max_new_tokens=12,
    relevance_method="combined",
)

result = calculate_relevance(
    "The color of grass is", config=config
)

print(result["generated_text"])
print(result["token_details"][0]["top_contributing_tokens"])

Append, then repeat

green joins the context before the next forward pass. Later relevance vectors can therefore point to prompt tokens and previously generated tokens.

How to read the result

Read across one row,
not down one column.

  1. 1

    Pick an output row. The first row explains why the model selected green.

  2. 2

    Scan its context. grass is strongest at 0.48, followed by is at 0.22.

  3. 3

    Move to the next row. The green column is now active because that token joined the context.

  4. 4

    Compare roles. Prompt tokens show grounding; generated tokens show self-conditioning.

Important: normalization happens independently per row. Compare tokens inside the same generation step.
03 · Relevance methods

Four methods, taught step by step.

Defaultcombined

Combined

A balanced first view that blends where information was routed with what the selected logit was locally sensitive to.

r = α · rattention + (1−α) · rgradient
  1. 1Compute the normalized attention vector.
  2. 2Compute the normalized gradient × activation vector.
  3. 3Blend them with alpha; default 0.5.
  4. 4Normalize the blended vector again.
Example with α = 0.60.6 × attention + 0.4 × gradient
Choose it when
You want a general-purpose trace
Main cost
Forward + backward pass per token
--method combined --alpha 0.6
Fastattention

Entropy-weighted attention

Uses the model’s attention routing, while giving focused heads more influence than diffuse heads.

whead = max(0, 1 − H(attn) / log C)
  1. 1Keep the configured fraction of upper transformer layers.
  2. 2Read each head’s last-query attention over the context.
  3. 3Weight heads by inverse normalized entropy.
  4. 4Dampen detected BOS sinks, aggregate, and normalize.
Interpretationfocused head → larger vote
Choose it when
You need a faster structural view
Main caveat
Routing is not causal proof
--method attention
Localgradient

Gradient × activation

Measures how strongly each input embedding participates in the selected next-token logit near the current input.

scorei = ‖ gradienti × embeddingi ‖2
  1. 1Attach a hook to the model’s input embedding layer.
  2. 2Select the logit for the greedy next-token ID.
  3. 3Backpropagate that scalar to every context embedding.
  4. 4Take the per-token L2 norm and normalize.
Interpretationlarger local sensitivity → larger score
Choose it when
You care about local sensitivity
Main caveat
Gradients can saturate or be noisy
--method gradient
Deeprollout

Attention rollout

Approximates how attention can carry information through the full stack instead of inspecting only upper layers.

A′l = 0.5 Al + 0.5 I  ·  R = A′L … A′1
  1. 1Average the attention heads in each layer.
  2. 2Dampen sink columns and normalize every row.
  3. 3Mix attention with identity to model residual flow.
  4. 4Multiply layers and take the last-token row.
Interpretationdirect + indirect layer paths
Choose it when
You want multi-layer flow
Main caveat
Long paths can become diffuse

04 · Honest tradeoffs

Useful for investigation.
Not a proof of causality.

Read the scores as model-behavior signals. They are strongest when used to compare tokens within one generation step and to triangulate across methods.

+ Strengths
  • Stepwise visibility. Every generated token receives its own explanation.
  • Full-context tracking. Separates prompt influence from self-conditioning on prior output.
  • Multiple signals. Attention, gradients, rollout, and a configurable blend.
  • Auditable artifacts. Raw vectors, ranked contributors, JSON, plots, and text.
  • Flexible access. Python API, CLI, local UI, and containerized services.
− Limitations
  • Approximate attribution. A high score does not establish counterfactual causation.
  • Compute grows quickly. A full model pass—and sometimes a backward pass—is performed per output token.
  • Greedy generation only. The current loop uses argmax, not sampling or beams.
  • Architecture constraints. The model must expose attentions and use a recognized embedding path.
  • Method sensitivity. Scores can vary with tokenizer, model, prompt, and attribution method.

Model compatibility

Decoder-only Hugging Face causal LMs.

Models must load through AutoModelForCausalLM, return attention tensors, and expose a supported embedding layer.

LLaMA-styleMistral-styleGemma-styleQwen-styleGPT-2-style

Not currently supported: encoder-decoder, masked-LM, classifier-only, multimodal, or unrecognized embedding architectures.

FAQ

Before your first trace.

Which method should I start with?+

Use combined for a balanced view. Switch to attention for a faster structural signal, or compare several methods when a conclusion matters.

Why are generated tokens contributors?+

Autoregressive models feed their prior output back into the next step. Including those tokens reveals when a response starts relying more on itself than on the original prompt.

Can I compare scores across prompts?+

Not as absolute measurements. Each relevance vector is normalized within its own step, so the safest comparisons are between tokens in the same context.

Does it work without a GPU?+

Yes for small models. Use sshleifer/tiny-gpt2 or distilgpt2 on CPU; larger models and gradient-based traces are much more practical on CUDA.
